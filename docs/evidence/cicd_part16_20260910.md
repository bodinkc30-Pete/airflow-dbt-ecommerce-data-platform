# PART 16 — CI/CD Runtime Evidence — 2026-09-10

## Scope

This evidence records CI/CD validation performed with synthetic data and isolated
runtime resources. No private seller, customer, creator, order, or tracking data
was used.

## Clean PostgreSQL bootstrap

A fresh PostgreSQL 17.10 container was used to simulate a new hosted runner.
Schema migrations `01..13` were applied twice successfully.

A clean-bootstrap defect was discovered in the governance migration: analytics
schemas did not yet exist before ownership/grant statements ran. The migration
was hardened with `CREATE SCHEMA IF NOT EXISTS` for the four analytics schemas.
After the fix, both migration passes completed successfully.

`database/ci/seed_synthetic.sql` was then applied twice. The verification query
returned exactly one synthetic row for each of the eight raw sources.

## Isolated Docker CI smoke

A separate Compose project was started on isolated host ports and its own named
volume. The main local stack remained healthy and was not reused as CI state.

Deployment validation passed for service health, Airflow heartbeats, non-root
execution, read-only mounts, no-new-privileges, loopback bindings, memory
ceilings, logging controls, named-volume persistence, and DAG imports.

The first smoke DagRun remained queued because a newly created Airflow metadata
database respected `is_paused_upon_creation=True`. Metadata confirmed the DAG
was paused. After unpausing, that same DagRun completed with 13/13 successful
tasks.

The smoke script was then changed to unpause before triggering. The DAG was
explicitly paused again and the updated script was executed end-to-end.

Final isolated smoke result:

- DagRun ID: `ci_smoke_20260910T003003Z`.
- script performed the unpause step itself.
- DagRun state: SUCCESS.
- task summary: 13/13 SUCCESS.
- every task completed on try 1.
- smoke script exit code: 0.
- runtime: approximately 84.9 seconds.

After validation, the isolated Compose stack, named volume, clean PostgreSQL
probe containers, and temporary Compose override were removed. No `project06-ci-*`
container residue remained and the main stack was still healthy.
